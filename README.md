# オフライン画像・文書 意味検索 PWA（offline-photo-search）

卒業研究（教育学部 技術・ものづくり教育コース）の開発リポジトリです。
スマートフォンのブラウザだけで動く「完全オフライン意味検索」PWA を開発します。

- 公開URL: https://224096-cmd.github.io/offline-photo-search/
- 検索は4段階構成（BM25 → 静的埋め込み → e5-small／Ruri → EmbeddingGemma 2）で、端末ごとに動く段階を使う
- 写真・文字・ベクトルは端末内（IndexedDB）にのみ保存し、外部へ送信しません

## 現在の状態

**v0.11** — サンプル刷新（実物調）・UI改善・バグ検証パス。

- **サンプル10件を実物調に全面差し替え**：架空の短文から、学校現場で実際に撮りそうな文書
  （遠足のお便り・調理実習計画・ボール盤実習プリント・理科実験記録・数学ノート・持久走大会要項・
  はんだ付けメモ・micro:bit プログラミング記録・進路だより・学級連絡板）の全文調テキストに変更。
  OCRで読んだ文書に近い評価・デモができる
- **UI改善（使いやすさ検証の反映）**：
  - 進行状況の表示を画面上部に固定（スクロールしても今の状態が見える）
  - 先頭に「使い方 3ステップ」の折りたたみガイドを追加
  - 検索欄で Enter キーでも検索を実行
  - 取り込み処理中はボタンを無効化（二重タップによる重複取り込みを防止）
  - BM25（単語一致）選択時は無関係な「実行方式」選択を非表示
  - BM25で一致0件のときに「意味検索を試してください」と案内（言い換えに弱い特性の体験がRQ3の入口になる）
  - 文書一覧は最新6件を表示し「全n件」フッターで総数を明示
  - モデル読み込み完了時に次の手順（②ベクトル化→③検索→④ベンチ）を案内
  - CSVの未計測欄は「—」で出力（null表記をやめ卒論の表にそのまま使える形に）
- **バグ検証パス**：スクリプト全体の構文検査に加え、検索ロジック（文字2-gram・BM25・内蔵ベンチ）を
  Node.js に抽出して実行テスト。ベンチ15問の正解IDがすべて文書側に存在すること、
  Recall@1/@3・MRR が正しく計算されること（BM25実測: R@1=67%・R@3=80%・MRR=0.767）、
  新サンプルへの検索挙動を確認済み（ブラウザ実機の最終確認は公開URLで行う）

**v0.10** — 精度評価ベンチ内蔵（RQ3）＋DL型OCR「PP-OCR系」接続（RQ2）。

- **④ 精度評価（ミニベンチ）**：学校文書20件・言い換え質問15問の内蔵評価セットで、現在の検索方式の
  Recall@1／Recall@3／MRR（正解の順位の逆数の平均）・1問あたり処理時間を自動集計。
  方式を切り替えて押し直すだけで、BM25／e5-small／Ruri／EmbeddingGemma 2 の定量比較（RQ3）が取れる。
  評価セットはJSONファイルで差し替え可能（公開データセット由来のセットを後日提供予定）
- **DL型OCR接続**：OCRエンジンに PP-OCR系（ppu-paddle-ocr・v6多言語モデル＝日本語対応・WASM実行）を追加。
  同じ写真をTesseract.jsと読み比べることでRQ2の比較データが取れる（実験的・初回はオンライン必須）
- 書き出し（⑤）にベンチ結果・エンジン別OCR計測を追加

## 開発フロー

1. 受け取った zip をこのリポジトリのフォルダに展開する
2. `git add -A` → `git commit` → `git push`
3. GitHub Actions が自動で Pages へデプロイ（Actions タブで進行確認）
4. スマホ・PCで公開URLを開いて動作確認

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `index.html` | アプリ本体（取込→OCR→保存→4方式検索→ベンチ→書き出し） |
| `sw.js` | Service Worker（オフライン用キャッシュ） |
| `manifest.webmanifest` / `icon-*.png` | ホーム画面インストール用 |
| `.github/workflows/pages.yml` | GitHub Pages への自動デプロイ設定 |
| `.nojekyll` | GitHub Pages の Jekyll 処理を無効化 |
